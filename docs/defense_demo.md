# Сценарий демонстрации на защите

## Подготовка заранее

Убедиться, что Docker Desktop запущен. В папке проекта выполнить `docker compose up -d db mock-api dashboard`, затем `docker compose run --rm etl python -m etl.cli full`. Проверить <http://localhost:8000/docs> и <http://localhost:8501>. Сохранить презентацию и снимки панели для показа при задержке запуска.

## Демонстрация за 3–4 минуты

1. Показать схему единого конвейера: имитатор API → исходный слой Bronze → очищенный Silver → витрины Gold → проверки качества → классификация → панель.
2. Открыть `/stats` в документации имитатора. Пояснить, что источник синтетический и не подключён к IntraService.
3. Открыть панель. Показать графики потока обращений, сроков и нагрузки, затем раздел «Качество и запуски» с шестью проверками.
4. В разделе «Классификация» показать сравнение двух методов и рекомендации для открытых обращений. Сказать, что на новых шаблонах центроидный метод дал 20,28 % точности и мера F1 составила 0,0808. Поэтому категория не назначается автоматически.
5. Выполнить в PowerShell `./scripts/incremental-demo.ps1`. Сценарий создаст 100 новых заявок и изменит 20 существующих, затем запустит выборочный конвейер.
6. Обновить данные в панели. Показать новое число обращений, успешный запуск и число полученных изменений. Затем показать [график испытания](../artifacts/final_model/benchmark_stable.svg): на уровнях 30 300–40 000 заявок полный конвейер занял 10,418–15,457 с, выборочный — 0,422–0,499 с.

## Важные пояснения комиссии

- **Почему источник не IntraService?** Доступ к корпоративной системе и её данным не требовался для автономного макета. Интерфейс воспроизводит смысл сущностей Service Desk, но совместимость с закрытым API IntraService не проверена.
- **Где инженерия данных?** В постраничном извлечении, выборочной загрузке, истории версий, типизации, обогащении, контроле качества, витринах, сохранении состояния и оценке времени конвейера.
- **Почему три слоя?** Bronze сохраняет значения и версии полученных сообщений, Silver — одну актуальную типизированную запись на обращение, Gold — рассчитанные показатели для панели и рекомендации категории.
- **Что означает «распределённая»?** Компоненты работают как отдельные сетевые службы в контейнерах на одном компьютере. Отказоустойчивость кластера этим не подтверждается.
- **Есть ли ИИ?** Реализовано сравнение двух методов классификации темы. Качество на новых формулировках низкое; поиск похожих закрытых заявок и проект ответа остаются направлением развития.
- **В чём ограничение результата испытания?** Измерения относятся к синтетическому набору и одному компьютеру. Отношение времени 24,69–30,98 характеризует весь конвейер, включая переобучение модели при полном запуске. Само построение витрин в выборочном режиме в этом опыте было немного медленнее полного.
